## Your workstream: D — Structured symptom assessment ("Belirti Değerlendirme") page
You own: src/medrag/assess/** (new package), src/medrag/api/routes/assess.py, src/medrag/web/assess.html, src/medrag/eval/assess_cli.py (+ scenario data module), .github/workflows/assess.yml, tests/test_assess_*.py.

Goal: make the assistant feel like a careful doctor taking a history, while staying safe (no diagnosis, no prescriptions/doses). Stateless API (the client sends everything back each time; no server-side storage of health data):
1. `POST /api/assess/start` {complaint: str (required, ≤500), age: int?, sex: "kadın"|"erkek"|null, pregnant: bool?, chronic: [str]?} → {emergency: bool, emergency_text?: str, questions: [{id, text, type: "single"|"multi"|"scale"|"text", options?: [str], why?: str}] (3–6 focused follow-ups: onset/duration, severity, associated symptoms, red flags relevant to the complaint, risk factors), disclaimer}. If rule-based red flags already fire on the complaint (reuse `medrag.chat.triage.check_emergency` plus your own red-flag rules), return emergency immediately with the 112 message and no questions.
2. `POST /api/assess/finish` {complaint, profile, answers: [{id, question, answer}]} → {level: "emergency"|"today"|"soon"|"home", level_label (Turkish: "Hemen 112'yi arayın" / "Bugün bir hekime başvurun" / "Birkaç gün içinde randevu alın" / "Evde izleyebilirsiniz"), summary, reasons: [str], red_flags_to_watch: [str] (when to escalate), self_care: [str] (only for soon/home; generic, no meds/doses), sources: [{n, title, url, source, license}], disclaimer}.
   - Ground the explanation in retrieved sources (retriever on complaint + key answers) and cite them.
   - Deterministic red-flag rules (age-aware: infants < 3 months with fever, pregnancy + bleeding/abdominal pain, chest pain with exertion/sweating/radiation, sudden severe headache, neuro deficits, breathing difficulty, high fever + neck stiffness/rash, suicidal thoughts, etc.) set a minimum level; the LLM level can only RAISE the final level, never lower it below the rule minimum. Unknown/unparseable LLM output → conservative default ("today").
   - LLM outputs strict JSON; implement robust extraction (code fences, trailing text), pydantic validation, one repair retry, configurable model (default `auto`; make it easy for the lead to switch to e.g. `deepseek-v4-flash` after evaluation) and temperature.
   - Never output diagnoses as certainties; phrase as possibilities only if needed; never drug names with doses.
3. `src/medrag/web/assess.html`: a modern, simple, mobile-first step-by-step wizard (390px wide must look great, no horizontal scroll, light/dark): step 1 complaint + optional profile (age, sex, pregnancy if female, chronic conditions chips), step 2 questions one card at a time with chips for options and a progress indicator, step 3 result card with the level badge (base.css classes `badge level-emergency|level-today|level-soon|level-home`), summary, reasons, "Şunlar olursa hemen başvurun" list, self-care, sources, disclaimer, restart and "Sohbette devam et" (links to `/?q=<urlencoded question>` — the chat page will support prefill). Emergency at any point → prominent 112 alert (`alert alert-danger`) with a `tel:112` link. Include `<nav id="app-nav"></nav>`, `/static/base.css`, `/static/common.js`. Accessible (labels, focus management between steps, aria-live).
4. Eval (`assess_cli.py` + `.github/workflows/assess.yml`, workflow_dispatch with optional `model` input): ≥15 scenarios, each with a hidden case description, an expected minimum level and a maximum acceptable level (to catch over-triage for mild cases). An LLM "simulated patient" answers the generated questions from the hidden description; report per-case level vs expected, over/under-triage counts, JSON validity rate, latency; write eval/assess_results.md; exit non-zero on any under-triage of emergency cases.
